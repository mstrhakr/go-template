Small packages with clear responsibilities

cmd/server/       executable, signals, server lifecycle, health probe
internal/config/  environment parsing and validation
internal/web/     HTTP routes and embedded landing page
docs/content/     documentation source
docs/layouts/     local Hugo templates
docs/static/      documentation styles
.github/          CI, opt-in publishing, dependency updates

Keep wiring in cmd/server and behavior in focused internal packages. Add domain packages when actual requirements arrive; do not start with generic repository, service, or dependency-injection abstractions.

Runtime contract

  • GET / serves an embedded page; no working-directory assumptions.
  • GET /healthz returns {"status":"ok"}. It is process liveness, not a dependency readiness check.
  • Unsupported paths return 404; unsupported methods return 405.
  • JSON lifecycle logs go to stdout. Configuration errors exit nonzero.
  • HTTP timeouts bound slow clients; SIGINT/SIGTERM allow up to ten seconds for shutdown.
  • The -healthcheck flag probes the configured address with a three-second timeout.

Deliberate omissions

No database, authentication, scheduler, telemetry service, or frontend toolchain is preselected. There are no protected routes yet. Before adding sensitive data or administrative operations, add authentication, authorization, request limits, and appropriate tests. Review the starter Content Security Policy before adding scripts, styles, or remote assets.

Reference projects

The structure follows patterns found in network-list-sync, audplexus, and PrintMaster: single-binary services, focused packages, explicit lifecycle management, and multistage builds. No application code or domain dependencies were copied.
