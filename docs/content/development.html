Daily commands

Install Go 1.27.4, Node 24, GNU Make, and a C compiler (Go race tests use CGO). On Windows, use an appropriate Make/GCC toolchain or WSL for the local full suite; native Windows behavior is separately checked by CI. Hugo and Docker are optional until working on their surfaces.

make setup       # once: locked npm tools and Playwright browsers
make test        # all Go, JS/unit/API, and desktop/mobile browser tests
make check       # above plus vet, formatting, build, assets, contracts
make fmt         # format Go code
make test-go      # focused race-enabled Go checks
make test-js      # Node unit tests and browserless HTTP tests
make test-e2e     # Chromium, Firefox, WebKit, mobile Chromium
make check-workflows # workflow lint and token/pin policy
make check-security  # npm audit and Go vulnerability analysis
make check-container # Docker build and vulnerability scan
make docs         # default docs build
make docs-contracts # opt-in preview including contracts

Linux browser system dependencies can be installed with npm exec -- playwright install --with-deps chromium firefox webkit. Run privileged OS installation yourself when your environment requires it. VS Code's default Test task runs make test. No separate test.sh is needed: a wrapper would only delegate to Make, never maintain a second test list.

Playwright starts/stops a dedicated Go server at 127.0.0.1:18080 and refuses to reuse an unrelated existing listener. Two workers bound memory use; tests do not retry failures. Reports and failure traces are local ignored artifacts. Node unit tests use the built-in runner; HTTP and browser tests use Playwright.

Go tests use the standard testing and httptest packages. Add table-driven configuration tests and handler tests near the implementation. For an individual package, run go test -race ./internal/web.

Dependencies and updates

The service uses only the Go standard library, so there is no go.sum yet. Use go get module@version and go mod tidy when adding dependencies, and commit both module files. Docker copies both automatically.

Dependabot checks Go modules, npm, SHA-pinned GitHub Actions, and Docker images weekly. Review updates rather than automatically merging them. Go starts at 1.27.4 and Hugo at 0.169.0, the latest stable releases checked for this first pass.

When updating Go, align go.mod and the Dockerfile tag/digest. When updating Hugo, update the version and official release SHA-256 in .github/actions/setup-hugo/action.yml; Hugo's binary is not managed by Dependabot. Install that same Hugo version locally from the official release, checking its checksum before running it.

htmx is pinned in package-lock.json and committed under internal/web/static with its license and SHA-256 metadata. After an intentional package update, run npm run assets, review the generated changes, then run make check-assets. Builds do not download browser code from a CDN. Node is not required to run an already-built executable or container.

GoReleaser, govulncheck, actionlint, Buildx and the scanner image have explicit pins too. Dependabot does not update every executable version/checksum embedded in scripts or composite Actions; review those manually. Direct Action pins are not a blanket guarantee about all upstream downloads or transitive dependencies.

Documentation

Content lives in docs/content/. Existing pages use HTML with TOML front matter; Hugo also supports Markdown pages. Add a title and weight to include a page in navigation. Layouts and CSS are local, avoiding theme/submodule drift. CI builds the site with a project subpath to check GitHub Pages compatibility.

Continuous integration

Protect main; use short-lived branches and squash PRs with Conventional Commit titles. No permanent dev branch, mandatory second reviewer, or local commit hook. The optional VS Code extension assists authoring; CI checks the PR title and the squash defaults use it. Maintainers must preserve that checked message on merge.

CI detects changed surfaces and runs only relevant read-only jobs. Unknown paths/shared tooling run broadly; failed detection or cancelled/failed checks fail the final CI gate. Contract-only edits skip app jobs unless mixed with code. When contract publication is enabled, those edits also validate the docs build.

Native Go CI covers Linux x64, Windows x64, macOS x64 and macOS ARM64. Cross-compiling releases is not native execution evidence. Browser tests on Linux exercise Chromium, Firefox and WebKit; WebKit is not a native Safari run, and mobile emulation is not a physical-device test.

PR jobs never receive publishing secrets or write scopes. Privileged events do not execute PR source; no public-PR self-hosted runners or cross-trust caches. Dependency scans run on relevant changes and a schedule. Protected-main CodeQL has security-report write scope, not PR access or package publication rights.

See the contract guide before behavioral changes. Structure checks do not approve a requirement; report actual executed checks and remaining gaps.
