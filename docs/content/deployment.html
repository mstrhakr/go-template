Docker Compose

cp .env.example .env
docker compose up --build -d
docker compose logs -f
curl http://localhost:8080/healthz
docker compose down

Compose reads .env for the host port and log level. The multistage image contains a static binary and CA certificates, runs as UID/GID 65532, and provides a built-in health check. Compose uses a read-only filesystem, drops capabilities, and prevents privilege escalation. No secrets, source files, shell, or docs are included in the runtime image.

The default host binding is 127.0.0.1. For remote use, put a TLS reverse proxy in front of it. If the proxy is another container, connect it to the same Docker network and use app:8080 instead of loopback. Do not expose future administrative routes without authentication.

Container registry (off by default)

  1. Set the repository Actions variable PUBLISH_CONTAINER to true.
  2. Run the “Publish container (opt-in)” workflow manually on the default branch.
  3. After tests pass, it publishes amd64 and arm64 images to ghcr.io/owner/repository:sha-FULL_COMMIT_SHA, with lowercase names.

It uses the built-in GitHub token; no personal access token is required. New GHCR packages are private by default, but existing packages retain their visibility. Verify package access before enabling this workflow. There is no automatic publication on pushes or tags.

GitHub Pages (off by default)

A private repository does not guarantee a private Pages site. Pages availability and private-site access controls depend on your GitHub plan. Treat publishing as public disclosure unless you have explicitly verified access controls. No repository visibility or Pages setting is changed automatically.

  1. Review the generated content and remove anything that must remain private.
  2. When ready, select GitHub Actions as the Pages source in repository settings.
  3. Set the Actions variable PUBLISH_DOCS to true.
  4. Run “Publish documentation (opt-in)” on the default branch and explicitly confirm publication. Optionally require approval on the github-pages environment.

The workflow derives the base URL from GitHub Pages, so project paths and custom domains do not require hardcoded repository names. Preview locally with make docs-serve while publishing remains disabled. Changing either opt-in variable back to false prevents future runs, but does not delete already published sites, packages, or artifacts.
